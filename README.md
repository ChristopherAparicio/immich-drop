# Immich Drop — sovereign staging fork

Collect photos and videos through a temporary browser invitation without
exposing Immich and without giving the public-facing service an Immich API key.
Uploads are written to a bounded NAS staging directory. Importing accepted
files into Immich is a separate, local operation.

This repository is a security-focused, clean-history derivative of
[`Nasogaa/immich-drop`](https://github.com/Nasogaa/immich-drop). It preserves
the upstream MIT licence and the useful invitation/mobile-upload concepts, but
replaces the direct-to-Immich backend. See [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

## Security model

```text
visitor
  │ HTTPS
  ▼
Caddy on the VPS ── bounded upload guard
  │ dedicated WireGuard peer; no durable VPS storage
  ▼
NAS upload filter ── exact method/path allowlist
  │ isolated Docker network; no Immich or LAN route
  ▼
Immich Drop ── /incoming/<opaque invite id>/{partial,completed}
```

The public service:

- has no Immich credential, Docker socket, public administration route, file
  listing, preview, or download route;
- requires an opaque invitation, password, and finite expiry;
- reserves byte and file quotas transactionally before accepting data and
  applies immutable cumulative attempt/ingress budgets to each invitation;
- accepts only explicitly configured photo/video profiles and verifies both
  filename extension and file signature;
- writes fixed-size resumable chunks to server-generated `.part` files and
  atomically renames a validated completed file;
- deduplicates completed content only within the same invitation using a
  server-computed SHA-256, while retaining a bounded temporary receipt so a
  lost final response can still be resumed safely;
- bounds both concurrent chunk readers and each chunk's absolute read time;
- encrypts resumable browser metadata with a session-scoped key instead of
  leaving invitation tokens or visitor filenames in clear browser storage;
- refuses to start when its marker-backed staging mount is absent;
- keeps public HTML, CSS, and JavaScript local: no CDN, analytics, fonts, or
  telemetry service.

The absence of antivirus is deliberate. Staging prevents untrusted files from
entering Immich automatically, but does not prove that a media file is safe.
The operator remains responsible for deciding what to import.

## Invitations

Each invitation has immutable public policy:

- `photos`, `videos`, `photos+videos`, or `photos+live` media profile;
- expiry, per-file ceiling, file-count ceiling, and aggregate byte quota;
- one logical destination label mapped below the configured staging root.

Passwords are generated by default and stored only as Argon2id hashes. Custom
passwords are accepted through a hidden prompt or an owner-only password file,
never as a command-line value. The public token is stored only as a hash.

Typical local administration:

```bash
python -m app.cli init --yes
python -m app.cli open --label "Family weekend" --profile photos+videos --ttl 48h
python -m app.cli list
python -m app.cli close <id-or-prefix>
python -m app.cli sweep
```

The CLI prints a link and generated password once. Send them through separate
channels. Administration is local/forced-command only; do not reverse proxy a
CLI or database endpoint.

## Storage

The configured incoming root must be a dedicated NAS mount with a filesystem
or dataset quota. The application also enforces a global byte budget and a
fixed free-space reserve, including bytes reserved but not yet written. A
single embedded maintenance loop releases abandoned partial reservations.

```text
incoming/
  .immich-drop-root
  <opaque-invite-id>/
    partial/
    completed/
    orphaned/   # completed files unknown to state.db, kept for operator review
state/
  state.db
```

Original names are bounded metadata only. Disk paths use server-generated UUIDs
and the validated extension. Archives, SVG, PDF, executable content, and unknown
formats are refused and are never unpacked.

Deduplication saves staging space and invitation quota, not upload bandwidth:
the service can identify identical content only after receiving and validating
the complete file. It never compares or links content across invitations and
never accepts a client-provided whole-file hash as proof of a duplicate.
`UPLOAD_WORK_MULTIPLIER` defaults to `3` and bounds cumulative upload-creation
attempts (including policy or quota rejections), chunk requests, and declared
chunk bytes from the invitation's file, quota, and fixed chunk limits. The value
is captured when an invitation is created and is capped at `10`; changing it
does not weaken existing invitations.

## Local development

Create private writable directories and their marker, then use the example
Compose file or run the service directly. Never reuse production state or
incoming directories for tests.

```bash
cp .env.example .env
umask 077
mkdir -p .local/incoming .local/state
openssl rand -base64 48 > .local/session-secret
docker compose -f compose.example.yml run --rm --build immich-drop \
  python -m app.cli init --yes
docker compose -f compose.example.yml up --build -d
```

On a native Linux Docker host, make the two bind-mounted directories writable
by UID/GID `65532:65532` before the one-time `init` command. Docker Desktop
handles its bind-mount ownership mapping.

The example binds to loopback. Production publishes no container port: Caddy
on the VPS reaches the NAS service only through the dedicated WireGuard peer
and filters maintained in the companion `immich-share` repository.

## Verification

```bash
python -m pytest
python -m compileall -q app
node --check frontend/app.js
python scripts/check-public-tree.py
docker build -t immich-drop:test .
IMMICH_DROP_TEST_IMAGE=immich-drop:test scripts/container-e2e.sh
```

Before a release, also run dependency, image, secret, history, SBOM, and route
regression scans. Deployment remains closed until quota races, resume, expiry,
traversal, type spoofing, log redaction, missing-mount, low-disk, and external
no-read tests pass.
